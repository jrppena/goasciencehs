## Design Specificity Verdict

**Starts here:** the admin is authored for this school, not just themed like it. It inherits the "Official Record" language down to the details — JetBrains Mono for order numbers, dates, and counts (genuinely data here, not costume), Anybody caps on H1/H2, School Blue on white surfaces, Pending gold reserved for real status. An unrelated CMS admin could not wear this unchanged. Where it thins out is task shape, not style: the visual language is specific, the workflow is generic. The two things unique to GSHS — advisories carrying the principal's signature, and the school's approval norm — are buried in a small sidebar select and an unstructured publish toggle.

**Deterministic scan:** `impeccable detect --json src/app/admin src/components/admin` → **0 findings** (exit 0). I validated the detector against two deliberately flawed fixtures (HTML and TSX) and it caught gradient text, low contrast, and glow shadows, so the clean result is meaningful — but the TSX rule set is narrower (inline-style contrast wasn't caught in the TSX fixture), so 0 findings proves absence of slop patterns, not accessibility.

**Visual overlays:** not available. No browser automation tool is exposed in this session, so no live overlay/console pass ran; findings come from source review and the detector only. No false positives to reconcile.

## Overall Impression

A calm, well-mannered extension of the public site — and unusually good at the unglamorous stuff (pending states on submits, specific field hints, two-step deletes, `noindex` everywhere). Its weaknesses are not visual; they're about orientation (where am I, what is happening) and the two workflows that matter most in this product: getting an advisory out fast and keeping lists workable as they grow. The single biggest opportunity is to let the dashboard behave like the school's control room instead of two count cards.

## What's Working

1. **The identity carries.** Mono metadata, caps, and School Blue make the admin read as the same institution as the public site. In an admin, the mono treatment is functional — order, counts, dates are the data — so the system's citation typeface earns its place.
2. **Inline hints are specific and load-bearing.** "Required for Advisory posts", "Blank renders the 'To be announced' placeholder", "Lower numbers appear first", "Separate paragraphs with a blank line" — this is help written by someone who knows where staff will hesitate.
3. **Care is present in the basics.** Primary submits show "Saving…" and disable; login shows "Signing in…"; deletes require a two-step confirm; pages are `noindex`; `aria-invalid` marks failed fields; lists show counts and empty states.

## Priority Issues

### [P1] Nav loses "where am I" on every sub-page
`admin-nav.tsx:27` matches `pathname === item.href`, so from `/admin/news/<id>`, `/admin/about/core-values`, or any Academics page, **no nav item is highlighted**. Staff navigating deep lists must re-derive their location from page content alone.
**Fix:** active = longest prefix match (`pathname === href || pathname.startsWith(href + "/")`), keep `aria-current="page"`.
**Suggested command:** `/impeccable polish`

### [P1] No error or loading boundary in the admin
There is no `error.tsx` or `loading.tsx` anywhere under `src/app`. Pages are `force-dynamic`, so every navigation blocks on Mongo with zero feedback, and any thrown error (DB unreachable, expired session making an action throw "Unauthorized") lands on Next's stock error screen outside the admin shell.
**Fix:** add `src/app/admin/(dashboard)/error.tsx` with a retry and "Back to dashboard", plus a `loading.tsx` skeleton in the card rhythm. For actions, return error state instead of throwing where possible.
**Suggested command:** `/impeccable harden`

### [P1] Field errors and hints aren't programmatically tied to their inputs
Every form sets `aria-invalid` and renders an error `<p>`, but the admin contains **zero** `aria-describedby` usages (39 `htmlFor`s). Screen-reader users hear "invalid entry" with no explanation. The inline delete confirm has the same gap: the confirmation text appears unannounced and focus drops to `<body>` when the clicked Delete button unmounts.
**Fix:** give each hint/error an `id`, wire `aria-describedby` on the control; announce confirms with `role="status"` and move focus into them; Escape should cancel.
**Suggested command:** `/impeccable audit`

### [P2] Lists don't scale past a pageful
News, Faculty, Testimonials, About lists, and Academics lists have no search, no status filter, no pagination, and no bulk actions. Publish/feature/hide are one form per item. Reordering means opening each record: the order field and the list are never on screen together, so staff must remember positions.
**Fix:** status/category filter row with counts, pagination or "load more", bulk select for publish/hide, and in-place up/down (or drag) reordering on the list itself.
**Suggested command:** `/impeccable shape` (plan the list UX), then `/impeccable polish`

### [P2] The Advisory path — the highest-stakes content — gets no special care
Signatory name/role are always visible though only required for Advisory; there is no preview of the notice; on mobile the publishing sidebar stacks below a 16-row body textarea, so "Save changes" sits below the fold; there is no confirmation or checklist before publishing an advisory.
**Fix:** reveal signatory fields when Category = Advisory with the requirement stated up front; add "Preview" / "View on site" from the form; make the save/publish row sticky on mobile.
**Suggested command:** `/impeccable distill` (progressive disclosure), then `/impeccable polish`

## Persona Red Flags

**Alex (Power User):** No keyboard shortcuts; no bulk publish/unpublish; every toggle is a full round trip with no pending indicator; no way to filter straight to Drafts; reordering requires editing number fields record by record. Moderation of a news backlog is linear work.

**Sam (Accessibility):** Errors and hints orphaned from their fields (`aria-invalid` with no `aria-describedby`) — a failed save is a dead end. Focus is lost when Delete swaps to its confirm row; no Escape to cancel. No skip link in the admin shell even though `main id="main"` exists. The computed "Faculty and staff" value sits in a `disabled` input some AT skip. Nav `aria-current` works — until a sub-page, where it disappears entirely.

**Mara (project persona — front-office staffer publishing a suspension on her phone before the storm):** Seven nav items hide behind a horizontal swipe; the signatory fields she must fill are buried at the bottom of the sidebar; Save sits below a 16-row body field; there is no preview to check the notice; and if she misses the signatory, the server answers "Please fix the highlighted fields." with no sign that only Advisory requires it.

## Minor Observations

- Four near-identical delete-confirm components (news, faculty, testimonials, plus the About/Academics pair) — consolidate to one two-step `ConfirmDeleteButton` so behavior can't drift.
- `CardTitle` renders a `div`, so section cards ("News", "Faculty", "Core values") never appear in a screen reader's heading outline.
- The signed-in email is hidden below `lg`; on the phone the admin can't confirm which account is active.
- Login has no show-password toggle and no "contact the ICT coordinator" line; the error copy itself is correctly vague.
- The `main id="main"` anchor implies a skip link in the admin that doesn't exist.
- Detector note: 0 findings is credible (fixture-validated) but TSX rules are narrower than HTML — treat it as slop-pattern clearance, not full accessibility proof.

## Questions to Consider

- What would the dashboard look like as the school's control room — latest advisory, drafts awaiting approval, this week's changes — instead of two count cards?
- Given the site is the official record, should publish/unpublish leave a who/when trail, or be undoable?
- Could "Order" disappear in favor of in-place reordering, so nobody has to hold a list in their head?
- Should advisories have an explicit "Ready for the principal" state before they can go public?
