### Design Specificity Verdict

**LLM assessment**: Authored with this brand and for this data — the shell identity, notice stripe on the dashboard's latest advisory, advisory-conditional signatory fields, "learners", honorifics, and "To be announced" placeholders are real. Structurally, ~80% is domain-neutral CMS furniture: the three lists repeat one component, About/Academics are one config-driven form, and the toolbar/filters/primitives are relabel-able. Decisively, the school's strongest product rule — `ADVISORY_VERIFICATION_RULE`, "official only if signed" — appears only on the public article and never at the moment of writing or publishing. The skin is specific; the workflow isn't yet.

**Deterministic scan**: `detect --json` → `[]`, exit 0 across 110 files (99 app + 11 components; 71 TSX). Re-run with `--no-config` also clean; zero `impeccable-disable` comments; an independent slop-pattern grep (thick left borders, hover shadows, gray-on-color, gradients) found nothing. **Visual overlays**: none available, and none claimed. ### Overall Impression

This admin is now safe by construction in the places that matter most: publishing is deliberate, deletion is two-step, retrieval is fast, and the design system is genuinely shared. What it still lacks is the *end* of the loop — staff can't see what they're about to publish, are never told it worked, and only one editor warns before losing work. The single biggest opportunity: treat an advisory's path to the public record as the product, with preview, signature, and confirmation built in.

### What's Working

1. **The bulk toolbar is spec-quality** — pins while selected, select-all with indeterminate state, live count, per-action pending, completion announced and focused, destructive action routed through the shared confirm (`components/admin/bulk-toolbar.tsx`).
2. **The two-step confirm is designed for people** — quotes the record, `role="alert"`, Cancel receives focus, Escape aborts, focus returns on cancel (`components/admin/confirm-action-button.tsx`). Exactly right for office staff acting on official records.
3. **Real design-system fidelity with no-JS commitments** — public tokens throughout, notice-stripe callback on the dashboard, aria wiring via the shared `FormField`, and GET-form filters that still work without JavaScript.

### Priority Issues

**[P1] Publishing has no preview, no confirmation, and no acknowledgement**
- **What**: A draft can't be previewed anywhere; "View live" exists only after publishing (`news/news-form.tsx`). Publish is one submit (form) or one click (list), with no summary, and success is a silent redirect. The signature-verification rule never appears in the admin.
- **Why it matters**: PRODUCT.md says approvability outranks flourish; an unsigned advisory can reach the public record with one mis-click and the author can never verify the rendered signature block beforehand.
- **Fix**: Authenticated draft preview using the public article template; a publish confirmation summarizing title/category/date/signatory and stating "will be visible on the public site"; a persistent success acknowledgement; surface the verification rule inside the Advisory form.
- **Suggested command**: `/impeccable shape`

**[P2] Unsaved-work protection exists but only guards News**
- **What**: Only `news/news-form.tsx` calls `setIsBlocked`. Faculty, Testimonials, Settings, About, and Academics forms never register; `AdminListForm`'s Cancel is a plain Link.
- **Why it matters**: The shell advertises a guard it doesn't deliver — a rewritten story or quote can vanish with no warning.
- **Fix**: Extract a dirty-tracking hook (change + `beforeunload` + `setIsBlocked`) and use it in every editor; make Cancel a `GuardedLink` everywhere.
- **Suggested command**: `/impeccable harden`

**[P2] Row-level actions have no pending, success, or guardrail — and the risk posture is inverted**
- **What**: Publish/Unpublish, Feature/Unfeature, Hide/Show are bare server-action forms with no disabled/label change or status line (`news/page.tsx`, `faculty/page.tsx`, `testimonials/page.tsx`). Unpublish is confirmed; Publish is one click.
- **Why it matters**: On the rural connections PRODUCT.md names, a button that doesn't respond reads as broken → repeat clicks; and the consequential direction (publish) is the unguarded one.
- **Fix**: Reuse the bulk status/focus pattern for row actions; add pending labels; require an inline confirm for Publish with the signature summary.
- **Suggested command**: `/impeccable polish`

**[P2] Staff-facing language, record identity, and a missing type token**
- **What**: "Slug", "Tone", bare "Order", "entries", and icon selects whose options are component names (`FlaskConical`, `ShieldCheck`) in `about/field-config.ts`. About/Academics edit pages show only "Edit core value" with no record name or back link (`about/core-values/[id]/page.tsx`). Verified: `text-body-sm` is used in 5 places (`form-field.tsx:58,71`, `image-upload.tsx:109`, `news-form.tsx:264,271`) but **does not exist** in the type scale — hints/errors render at body size.
- **Why it matters**: Mila doesn't know what a slug or "FlaskConical" is, can't tell which of twelve core values she's editing, and the help text that should recede competes with labels instead.
- **Fix**: Rename/annotate jargon (icon previews, "URL address (auto-filled)"); add record-name + back link to About/Academics edit pages; define `--text-body-sm` (14px/20px) in `globals.css`, register it in the twMerge scale, and document it in DESIGN.md — or drop the class deliberately.
- **Suggested command**: `/impeccable clarify` (token belongs to `/impeccable typeset`)

**[P3] Mobile nav hides the current section**
- **What**: `AdminNav` is a horizontal scroller under `md` with no scroll-into-view for the active pill and no edge affordance.
- **Why it matters**: Principle 5 is "built for the phone in the barangay"; a user landing on Site settings may not see where they are or that more sections exist.
- **Fix**: Scroll the active item into view on mount and add a scroll affordance, or collapse to a disclosure/select under `md`.
- **Suggested command**: `/impeccable layout`

### Persona Red Flags

**Alex (power user)**: No sort anywhere; reordering is manual order integers one record at a time; select-all is scoped to rendered rows with no "all matching filters"; no duplicate for recurring advisories; Feature is per-row only, so a homepage refresh is N clicks.

**Sam (accessibility)**: Dashboard/summary cards use a `div` title (`ui/card.tsx:66`), so heading navigation is H1 → nothing there (Settings does it right); list-field Remove buttons have no per-row accessible names; login marks both fields `aria-invalid` when either fails and links no error via `aria-describedby`; `FieldError` has no live region; icon options are announced as component names.

**Mila (school office staff)**: No preview before the public sees a signed advisory and no "it's live" confirmation; Settings has two independent saves that can drop the other card's edits; "story missing" on the dashboard reads as damage; vocabulary shifts (posts/entries/statements/members); row Publish has the same weight as Feature/Edit/Delete.

### Minor Observations

- `text-body-sm` undefined — verified defect the detector cannot catch (fix is a token + twMerge registration + DESIGN.md line).
- No pagination; lists fetch and render everything (already known scope for scale).
- Dashboard's latest-advisory card keeps the notice stripe even for drafts.
- Delete-confirm text truncates at 14rem with the full string only in `title` (touch can't reach it).
- "View site" opens a new tab with no external-link cue.
- No "last updated"/audit metadata (schema lacks timestamps — deliberate follow-up).
- About/Academics empty states state the absence; News offers a next action.
- Row Publish one-click vs confirmed Unpublish (also in P2).

### Questions to Consider

1. If a notice is official only when signed, why doesn't the publish moment show or ask for that signature?
2. Should draft → review → signed → published be visible states rather than one click?
3. What should the admin promise when the connection drops mid-save — autosave, a local draft, or an explicit "not saved"?
4. If this were judged as a record book rather than a CMS, what would its audit trail show?
